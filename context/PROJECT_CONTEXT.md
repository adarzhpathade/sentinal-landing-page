# Sentinel Website - Project Context

## Overview

This project is the official landing website for **Sentinel**, an AI-native terminal designed for developers, DevOps engineers, system administrators, and power users.

The website is **not** a SaaS dashboard or an admin panel. It is a highly interactive product showcase whose primary purpose is to communicate Sentinel's philosophy, capabilities, and technical excellence through thoughtful design and immersive interactions.

The experience should immediately feel premium, modern, and engineered.

---

# Project Goal

The objective is to build a world-class landing page comparable to products such as:

- Linear
- Raycast
- Warp
- Cursor
- Vercel
- Stripe
- Framer
- Clerk
- Supabase

The website should make visitors feel that Sentinel is a mature, premium developer product before they even download it.

---

# Brand Personality

Sentinel should feel:

- Intelligent
- Minimal
- Technical
- Confident
- Premium
- Fast
- Secure
- Private
- Modern
- Engineering-focused

Avoid playful or overly corporate design language.

The product should feel like it was built by engineers for engineers.

---

# Design Philosophy

The design follows the principle:

> Less UI. More Experience.

Every element should have a purpose.

Whitespace is a design element.

Typography is the primary visual language.

Motion replaces decoration.

Interactions should communicate confidence rather than excitement.

---

# User Experience Principles

The website should create the feeling of using a premium desktop application instead of browsing a traditional marketing website.

Every section should naturally lead into the next through smooth transitions and carefully designed animations.

Navigation should feel effortless.

Scrolling should feel intentional.

Animations should never distract from the content.

---

# Target Audience

Primary users include:

- Software Engineers
- Backend Developers
- Frontend Developers
- Full Stack Developers
- DevOps Engineers
- System Administrators
- Cloud Engineers
- Security Engineers
- Linux Users
- Open Source Contributors
- Power Users

The audience is highly technical.

Avoid explaining basic developer concepts.

---

# Website Purpose

The website should accomplish the following:

- Introduce Sentinel
- Explain its capabilities
- Showcase its workflow
- Demonstrate product quality
- Build trust
- Encourage downloads
- Increase GitHub engagement
- Highlight privacy and offline AI
- Present Sentinel as a premium developer tool

---

# Visual Direction

The overall visual identity should be:

- Editorial
- Minimal
- Dark
- Spacious
- High contrast
- Typography-first

Avoid:

- Glassmorphism
- Excessive gradients
- Neon cyberpunk aesthetics
- Excessive shadows
- Overly colorful UI
- Busy layouts
- Generic SaaS cards

Every visual decision should reinforce simplicity and precision.

---

# Motion Philosophy

Animation is part of the interface—not decoration.

Motion should:

- Explain
- Guide
- Reveal
- Connect sections
- Create immersion

Motion should never exist purely for visual appeal.

Every animation must feel smooth, premium, and intentional.

---

# Tone of Voice

Content should be:

- Clear
- Technical
- Concise
- Confident
- Honest

Avoid:

- Marketing buzzwords
- Overpromising
- Excessive punctuation
- Emoji
- Clickbait headlines

Write like a premium engineering company.

---

# Website Architecture

The website is composed of independent sections.

Each section should have:

- Its own layout
- Its own animation timeline
- Independent components
- Reusable architecture

Global design consistency must be maintained across all sections.

---

# Responsiveness

The website must be designed desktop-first while remaining fully responsive.

Every interaction should gracefully adapt to:

- Large Desktop
- Desktop
- Laptop
- Tablet
- Mobile

Animations should scale appropriately across devices.

---

# Performance Philosophy

Performance is a feature.

The website should remain lightweight despite advanced animations.

Every animation must justify its existence.

Avoid unnecessary JavaScript execution.

Maintain smooth interactions across modern browsers.

---

# Accessibility

Accessibility should never be sacrificed for aesthetics.

The website should:

- Support keyboard navigation
- Maintain sufficient contrast
- Respect reduced motion preferences
- Use semantic HTML
- Preserve readability at all screen sizes

---

# Development Philosophy

Build for long-term maintainability.

Prioritize:

- Reusable components
- Modular architecture
- Clean code
- Predictable structure
- Scalable animation systems

Every implementation should be production-ready.

---

# AI Agent Instructions

When generating code for this project:

- Prioritize clean architecture over shortcuts.
- Follow the design system consistently.
- Keep components modular and reusable.
- Maintain premium spacing and typography.
- Avoid unnecessary dependencies.
- Ensure animations remain smooth and performant.
- Never compromise readability for visual effects.
- Treat every section as part of a cohesive product experience rather than an isolated webpage.

All future page specifications, animation descriptions, and component implementations should follow the principles defined in this document.
